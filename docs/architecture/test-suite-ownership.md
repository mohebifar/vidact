# Runtime and compiler test-suite ownership

- Decision state: Accepted
- Decided: 2026-08-21

## Context

The original browser corpus mixed three different contracts: direct runtime
primitive behavior, React-shaped source compiled through the Vidact Vite plugin,
and a checked-in JavaScript module generated by a Rust compiler example. This
made runtime tests look like compiler compatibility tests and required a byte-for-byte
generated artifact even after its browser consumer was removed.

## Decision

Each test suite owns one layer:

- `packages/runtime/test/` contains direct runtime browser tests. Its Vitest
  configuration does not load the Vidact compiler plugin.
- `tests/browser/corpus/apps/` contains React-shaped TSX mini apps. Its Vitest
  configuration loads `@vidact/vite`, so every app entry passes through the Rust
  compiler before Chromium executes it.
- `crates/vidact-compiler/tests/` owns compiler analysis and code-generation
  assertions. Compiler tests assert emitted semantics directly and do not depend
  on a checked-in JavaScript file under the browser corpus.
- The root test command invokes the runtime and compiler-backed browser suites
  independently.

Shared MutationObserver helpers live in `packages/test-support/`; their browser
tests run with the runtime suite because they exercise DOM observation rather
than compilation.

## Invariants

- A runtime test can run without `@vidact/vite` or the Rust compiler executable.
- A compiler browser-corpus test starts from `.tsx`, imports supported APIs from
  `react`, and is transformed by `@vidact/vite`.
- Direct runtime construction is supporting coverage, not evidence that a React
  source construct compiles correctly.
- Surgical code-generation ordering remains asserted in Rust, without a
  generated cross-suite fixture or a second executable emitter.
- `pnpm test` runs both `test:runtime` and `test:browser`.

## Alternatives considered

- **Keep all DOM tests in one browser corpus:** Fewer configurations, but suite
  names no longer identify whether the compiler participated and runtime
  regressions become coupled to compiler startup.
- **Keep the checked-in generated alias module:** Provides an exact textual
  golden, but the browser no longer consumes it and formatting creates an
  unrelated second owner. Rust semantic assertions already cover updater order
  and emitted operations.
- **Normalize formatting before comparing the generated module:** Avoids the
  immediate whitespace failure while retaining a dead artifact and an obsolete
  generator lifecycle.

## Consequences

Failures now identify their owning layer more clearly, runtime tests run without
compiler transformation, and the end-to-end corpus proves the public
React-to-Vidact path. The repository maintains two browser Vitest configurations,
and new tests must be placed according to whether compilation is part of their
contract.

## Verification

- `packages/runtime/test/` covers compiled state/updater behavior, internal
  keyed-array mechanics, lifecycle, direct DOM construction, and the public
  compiled-runtime surface.
- `packages/test-support/src/tests/mutations.browser.test.ts` covers the shared
  MutationObserver helpers through the runtime browser configuration.
- `tests/browser/corpus/apps/counter/CounterApp.browser.test.ts` and
  `tests/browser/corpus/apps/roster/RosterApp.browser.test.ts` exercise TSX
  compiled by `@vidact/vite`.
- `crates/vidact-compiler/tests/surgical_codegen.rs` verifies state lowering,
  updater bindings, import cleanup, and emitted operations within the sole
  executable compiler path.
- Run `pnpm check` to execute all layer-specific checks.
