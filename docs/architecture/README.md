# Vidact architecture decisions

These documents record accepted compiler/runtime contracts and their rationale. Plans describe intended work; architecture decisions describe boundaries the implementation must preserve.

- [Docs deployment through Nitro](docs-nitro-deployment.md) — the docs example keeps Vidact's routing and rendering while Nitro packages the client and SSR environments for Vercel.

- [React analysis boundary](react-analysis-boundary.md) — React Compiler supplies an owned typed CFG plus def-use facts while Vidact classifies supported syntax through OXC AST and semantic identities before lowering to its stable IR.
- [React Compiler SSA join snapshot](react-compiler-ssa-join-snapshot.md) — optimized predecessor and phi facts cross the patched Oxc seam as owned values and immediately lower into Vidact's validated reactive-flow graph.
- [Phi-derived static updaters](phi-derived-static-updaters.md) — React Compiler-proven joins lower from side-effect-free assignment regions into ordered source-mask updaters, including objects, arrays, and dispatched component types.
- [Structured synchronous region updaters](structured-synchronous-region-updaters.md) — React-validated switch/loop/label regions remain native Oxc AST inside static updater closures, preserving fallthrough and completion without a browser CFG interpreter.
- [Transactional publication and exception boundary](transactional-publication-and-exception-boundary.md) — cross-scope scalar/prop writes compute before commit and roll back in reverse order; native try/catch is accepted while upstream Rust React Compiler finally/explicit-throw gaps remain visible.
- [Opaque raw HTML subtrees](opaque-raw-html-subtrees.md) — React-shaped raw HTML is an explicit, Trusted-Types-aware opaque owner whose contextual parse and reversible child-list publication never destroy compiled children.
- [Patched Oxc submodule](patched-oxc-submodule.md) — the official Oxc repository stays pinned at a pristine upstream commit while Vidact's narrow React Compiler analysis seam is maintained as a deterministic patch series.
- [Component spans and compatibility corpus](component-spans-and-compatibility-corpus.md) — exact source spans join each React Compiler snapshot to its component, while a versioned manifest defines accepted, rejected, and intentionally different fixtures.
- [Keyed record updaters and owned blocks](keyed-record-updaters-and-owned-blocks.md) — stable keys retain row owners and nodes while static item/component updaters patch them; compiled array blocks can cross props with single-mount ownership.
- [Compiler-owned iterative JSX](compiler-owned-iterative-jsx.md) — keyed and explicit indexed record owners lower JSX maps and direct `for...of` accumulators without React element descriptors or a general reconciler.
- [Compiled component props, live ranges, and refs](compiled-component-props-live-ranges-and-refs.md) — reactive parent bindings feed child-local updater slots; adopted scopes, marker-derived live parents, range-owned dynamic values, and commit-time refs define component composition.
- [Deletion-aware reactive spreads and rest props](deletion-aware-reactive-spreads-and-rest-props.md) — resolved rest-object slots feed capability-imported intrinsic prop directives with deletion, event cleanup, explicit override precedence, and transactional rollback.
- [State slots, reducers, and disposal](state-slots-reducers-and-disposal.md) — `useState` and `useReducer` share one compiler-owned source slot, stable dispatch, batching, initializer, keyed-owner, and post-disposal failure contract.
- [Compiled lifecycle effects and commit phases](compiled-lifecycle-effects-and-commit-phases.md) — semantic dependency masks and per-run reactive snapshots drive post-DOM layout effects and cancellable passive effects with owner cleanup.
- [Hygienic local custom-hook expansion](hygienic-local-custom-hook-expansion.md) — semantic, hygienic pre-analysis expansion composes supported primitives under the caller's one scope while preserving reactive arguments, bounded rest arrays, and cleanup.
- [Function error boundaries and root reporting](function-error-boundaries-and-root-reporting.md) — transactional fallback recovery, logical-owner error ancestry, reset semantics, and root caught/uncaught callbacks avoid class components.
- [Deterministic test act draining](deterministic-test-act-draining.md) — test-only act scopes repeatedly drain Vidact passive work and native promise turns without adding production application bytes.
- [Compiler-owned memo and callback identity](compiler-owned-memo-and-callback-identity.md) — dependency-checked cached slots preserve observable memo and callback identity while publishing changes through static source masks.
- [Logical owner context propagation](logical-owner-context-propagation.md) — immutable provider frames travel with owners and updater callbacks while consumer-local slots bridge only the nearest provider value.
- [Owned external-store snapshots](owned-external-store-snapshots.md) — atomic read/subscribe/recheck bridges external libraries into equality-checked consumer slots with owner-scoped unsubscribe.
- [Deterministic logical-root identities](deterministic-logical-root-identities.md) — per-root prefixes and shared monotonic generators keep `useId` stable through updates and available to late logical descendants.
- [Owned logical portals](owned-logical-portals.md) — transaction-staged physical ranges retain logical context, IDs, lifecycle, and disposal while native events follow physical DOM bubbling.
- [Owned component result ranges](owned-component-result-ranges.md) — every compiled component returns a single-mount, marker-owned range that supports wrapper-free multi-root, scalar, and empty output with failure-atomic publication.
- [Single client compiler and runtime path](compiled-only-client-runtime.md) — surgical codegen and `mountCompiled` are the sole browser pipeline; obsolete spike emission, standalone updater scheduling, hook-index replay, and runtime `useState` fallback are removed.
- [Direct DOM-only construction](direct-dom-only-construction.md) — intrinsic JSX has one namespace-aware DOM construction backend; the discarded HTML-template experiment does not leave a mode option, marker ABI, or second runtime path.
- [React-shaped JSX type package](react-shaped-jsx-type-package.md) — `@vidact/react-types` reuses React's HTML attribute model while preserving compiled result values, native DOM events, namespace safety, and Vidact child ownership.
- [Namespace-aware DOM semantics](namespace-aware-dom-semantics.md) — compiler-carried host context constructs HTML, SVG, and MathML directly while deletion-aware styles, attribute policies, capture listeners, and controlled form timing patch retained nodes.
- [Development diagnostics and production error codes](development-diagnostics-and-production-error-codes.md) — development builds retain descriptive runtime failures while Vite production builds erase those strings in favor of stable compact codes.
- [Compact compiler/runtime ABI and measured bundle budgets](compact-compiler-runtime-abi.md) — compiler-owned tuples, constant and narrow source masks, production size budgets, and gzip-based acceptance criteria reduce the full runtime path without dropping DOM features.
- [Compiler-injected DOM capability reachability](compiler-injected-dom-capabilities.md) — lowered intrinsic JSX explicitly activates form, object-style, and SVG/MathML modules so default compatibility does not make unrelated chunks pay for them.
- [Versioned compiler targets and feature gates](versioned-compiler-targets-and-feature-gates.md) — typed build configuration, explicit compiler/runtime protocols, composed original-TSX source maps, and cache fingerprints make opt-in semantics reproducible across compiler callers.
- [Capability-owned runtime entrypoints](capability-owned-runtime-entrypoints.md) — compiler and Vite output compose canonical core, hydration, server, and feature modules directly; cross-product facades and forwarding source files are removed.
- [Node-API compiler distribution and shared tooling interface](node-api-compiler-distribution-and-shared-tooling-interface.md) — a stable `@vidact/compiler` facade, thin napi-rs adapter, shared CLI/Vite calls, version-matched native packages, and a Changesets fixed release group replace spawned compiler processes for npm consumers.
- [Versioned server markers and whole-root hydration](versioned-server-markers-and-whole-root-hydration.md) — browser-free lazy SSR and `v2` ownership ranges let the hydrate target claim matching nodes without churn and recover protocol/content mismatches at a defined root boundary.
- [Staged async resources and Suspense](staged-async-resources-and-suspense.md) — compiler-generated boundary factories, stable resource records, isolated owners, and an explicit pending hydration marker make lazy and promise suspension failure-atomic.
- [Interruptible transition publication](interruptible-transition-publication.md) — urgent and deferred queues, lane generations, slot revisions, and one compiled transaction prevent stale or partial transition publication.
- [Compiled Actions and owned form reset](compiled-actions-and-owned-form-reset.md) — FIFO action state, urgent optimistic layers, form-scoped status, permalink SSR, and field-owned reset semantics preserve atomic publication and compiled DOM ranges.
- [Retained Activity connections](retained-activity-connections.md) — hierarchical visibility connections preserve DOM and state while disconnecting Effects/subscriptions, deferring hidden work, and restoring server-hidden nodes without remounting.
- [Compiler-owned profiling and owner stacks](compiler-owned-profiling-and-owner-stacks.md) — staged Profiler boundaries measure fine-grained range/updater/Effect/scheduler work, while reactive debug values and logical owner stacks erase from production and unused builds.
- [Framework streaming, continuations, and trust boundaries](framework-streaming-continuations-and-trust-boundaries.md) — request-scoped caches, settled streams, Vidact continuations, explicit manifests and Server Function registries, boundary hydration, and owned head metadata form an isolated framework protocol whose checksum detects corruption rather than authenticating input.
- [Vidact Start file-route lifecycle](vidact-start-file-route-lifecycle.md) — one generated manifest drives nested matching, ordered loaders, Web handlers, SSR, and snapshot-backed hydration across target-specific Vite environments.
- [Render-flow normalization and identity](render-flow-normalization-and-identity.md) — exact React Compiler return sites lower into a Vidact DAG whose type/key/position rule preserves, replaces, or dispatches render alternatives without source-text inference.
- [Aligned render slots and identity dispatch](aligned-render-slots-and-identity-dispatch.md) — equal position/type/key alternatives, including nested JSX ternaries, retain their owned nodes through bindings, while owned choices or a narrow staged dispatcher replace only the identity that changes.
- [Runtime and compiler test-suite ownership](test-suite-ownership.md) — direct runtime browser tests live with the runtime, while the browser corpus contains only React-shaped TSX compiled through Vidact.
- [Owner-safe root replacement and HMR](owner-safe-root-replacement-and-hmr.md) — client and hydration roots replace owners failure-atomically, while Vite entries provide a lexical hot boundary and hydration-aware root reuse.
- [Lowered React dependency capsules](lowered-react-dependency-capsules.md) — reachable React-bearing package entries and directly imported published hooks compile through provenance-preserving target/source-linked capsules with bounded keyed fragments and dependency-owned memo analysis, but no package allowlist, runtime hook ABI, or React fallback.
- [shadcn Base UI as a compatibility corpus](shadcn-base-ui-compatibility-corpus.md) — the current shadcn Base UI registry is classified through fail-closed production compilation, while a local Fumadocs-style shell proves only the 35-module React-free subset and keeps browser ownership proof separate; Popover is a certified local replacement, not a Base UI Store compatibility claim.
- [Headless Fumadocs content boundary](headless-fumadocs-content-boundary.md) — Fumadocs discovers and orders server-side content while Vidact Start snapshots a bounded data model and local compiled TSX owns every browser node.
