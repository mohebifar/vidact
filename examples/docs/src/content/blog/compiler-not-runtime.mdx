<h1>Why Vidact puts reactivity in the compiler</h1>

<p className="lede">A setter already names what changed. If the compiler can also name every reader, the browser does not need to call the component again or discover a subscription.</p>

<p>React components are a useful way to organize UI code. In React, a state update normally schedules another render before React commits the necessary DOM changes. React Compiler can skip some of that work while keeping React's runtime model.</p>

<p>Vidact uses React Compiler analysis for a different target. It lowers supported components into DOM construction and ordered updaters. The component author still writes React-shaped TSX, but the browser runs a different program.</p>

<h2>A setter already tells us what changed</h2>

<p>Take <code>setCount(count + 1)</code>. The compiler assigns <code>count</code> a source ID and records every updater that reads it. At runtime, the setter marks that source dirty. The next batch runs the matching updaters in compiler order.</p>

<pre><code>{`setCount(...)
  → mark source:count dirty
  → select updaters that read source:count
  → mutate the owned DOM nodes`}</code></pre>

<h2>Static edges buy more than speed</h2>

<p>A source-to-updater link exists before the app ships. The compiler can print it in diagnostics, order it with other writes, include it in source maps, and reject cycles before code generation. The same representation drives client updates, server output, and hydration.</p>

<blockquote>Compilation is not an optimization around Vidact's runtime model. Compilation defines the runtime model.</blockquote>

<h2>The language contract gets stricter</h2>

<p>The compiler can only emit a static link when it can prove the relationship. A dynamic pattern that hides a dependency needs a compiler feature or a clear error. Vidact does not send unsupported code to a fallback renderer because that would change the update model without telling the author.</p>

<h2>The experiment has a clear failure test</h2>

<p>Vidact has to compile useful React-shaped applications while preserving the DOM nodes that an update does not own. The browser corpus checks both facts. It runs compiled apps in Chromium, Firefox, and WebKit, records mutations, and compares node identity across updates.</p>

<p>If the compiler needs broad rerenders or hidden runtime discovery to support ordinary application code, the model has failed on its own terms. That is more useful to learn than a benchmark number from a toy counter.</p>
