Vidact is a compiler for React-shaped components. You write function components, JSX, and hooks exactly the way you would in a React application. Instead of shipping React, Vidact compiles each component into plain DOM operations: create these elements once, and when this piece of state changes, update this text node.

Your component functions run **once**, when they mount. After that, only the DOM that depends on changed data is touched. There is no Virtual DOM, no reconciler, and no runtime that discovers dependencies while the page runs.

Here is a counter compiled by Vidact. Click the button and the number updates in place. The `Counter` function is never called again.

```tsx
import { useState } from 'react'

export function Counter() {
  const [count, setCount] = useState(0)

  return (
    <div>
      <button onClick={() => setCount((value) => value + 1)}>Increment</button>
      <output>Count: {count}</output>
    </div>
  )
}
```

## Why Vidact?

React's programming model is worth keeping. Components are functions, UI describes state, and hooks compose. Its runtime model costs you something for that: every state change re-runs component functions and diffs the result to find out what changed.

Vidact keeps the programming model and replaces the runtime model. Because the compiler can see your whole component, it knows ahead of time which expressions depend on which values. It emits exactly the DOM updates that are needed, in a fixed order, and nothing else.

- A compiled counter is 8 kB gzipped with the runtime included, because there is no reconciler to download.
- A state write runs a known list of updaters, so there are no surprise re-renders, no stale closures, and no `memo` needed to keep things fast.
- `useState`, `useEffect`, `useContext`, `useRef`, and the rest work the way you expect, and most React components compile without changes.
- Code Vidact cannot compile fails the build at the exact source location, rather than falling back to a slower path.

## What Vidact is not

Vidact is not a React renderer and it does not run React. There is no element tree to inspect, no Fiber, and no React DevTools. Class components, `React.Children`, and libraries that reach into React internals are not supported. If your application depends on those, read [React compatibility](/docs/reference/react-compatibility) before you start.

> [!WARNING] Vidact is in beta
>
> APIs are stabilizing and the supported subset of React is growing. Pin the compiler and runtime to matching versions and run your test suite against the versions you ship.
